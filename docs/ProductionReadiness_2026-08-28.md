## 直した欠陥
/
### モデルの入力が誤っていたもの（最も重い）

**`class_level` が常に 1**。`race_schedule` は距離もクラスも持たないのに、
`_schedule_row` が既定値（`distance=1200` / `class_level=1` /
`prize_yen=100万`）で埋めていた。学習データの `class_level` は
**2 が 77.6% / 4 が 19.8% / 5 が 2.6%** で、**1 も 3 も1件も存在しない**。
20 特徴量のうち1つに、モデルが学習中に一度も見ていない値を毎回渡していた。

当日ページ `DebaTable` の `.raceTitle` から読むよう変更。学習側の
`class_name` は「競走種類名称」で 普通 / 一般 / 特別 / 重賞 / 準重賞 の
5値しか取らないので、自由文をこの5値へ寄せてから学習側の `_class_level`
に通す。「特別」は場によって距離表記の前（園田）にも後（船橋）にも出る。

本番での推移が BigQuery にそのまま残っている:

| レース | 発火 | class_level |
|---|---|---|
| 船橋7R | 08:45 | 1.0（既定値） |
| 園田9R | 09:43 | 3.0（判定が不完全） |
| 船橋9R | 09:53 | **2.0**（正） |
| 園田10R | 10:17 | **4.0**（正・特別） |

### 一度も動いていなかったもの

- **`/refresh-live` が常に 0 件**。HTTP 経路が結果を渡さず、取得処理自体が
  無かった。ライブ層が一度も埋まらず、当日の先行レースが as-of 履歴から
  抜けていた。当日成績表 `RaceMarkTable` の解析を実装。
- **`/refresh-live` を誰も予約していない**。エンドポイントも設定値
  （`live_refresh_hours_jst`）もあるのに `plan_day` が積んでいなかった。
- **`OddsWin` は存在しないページ**。全レースでオッズ取得が失敗していた。
  HTTP 200 でエラー HTML が返るため気付けない。正しくは `OddsTanFuku`。

### ローカル緑・本番赤を作っていたもの

- **削除文にパーティション条件が無い**（`prediction` / `bet_candidate` /
  `entry_result_final` の3か所）。BigQuery は `require_partition_filter` を
  DML にも適用するので、書き込みが本番でだけ拒否されていた。
- 原因は **`execute()` に検査が無かった**こと。`query()` にはあった防護が
  DML に無く、DuckDB 側も素通しだったのでテストが全部通っていた。
  両バックエンドの `execute` に同じ検査を入れて塞いだ。

### 稼働そのものを止めていたもの

- **メモリ 1GiB**。推論中に上限超過（実測 1041 MiB）で 503。4GiB / 2 vCPU へ。
  起動回数は実測 65/日なので無料枠には収まる。
- **1レースの失敗が全体を止める**（2か所）。オッズ未公開レースは常にあるの
  に、そこで例外にするとスケジュール再照合まで巻き添えで止まっていた。
  オッズが無くても予測は残す（期待値が出ないので賭け金は 0 に縮退する）。
- **送信失敗が無記録**。Discord の 5xx が続くと未送信のまま痕跡が残らず、
  「停止したこと自体が通知されない」状態になっていた。

### テストの衛生

階層ベイズのテストが `jax` 未導入で失敗していた。`bayes` は pyproject の
任意 extra なので、`importorskip` で skip として報告するようにした。
導入するには `pip install -e '.[bayes]'`。

## ベット候補が 0 件になる理由（欠陥ではない）

1/4 Kelly × 上限 ¥3,000/レースだと、期待値 2.24 の馬でも
`0.077 × 0.25 × 3000 = ¥57` で最低賭け金 ¥100 に届かない。
**full Kelly が 0.133 以上でないと候補が立たない**設定になっている。
予測と通知は出るので、刻みを変えたい場合は `conf/ops.yaml` の
`bet.max_per_race` / `bet.kelly_fraction` を調整する。

## live に上げていない理由

paper は推論と通知を行い、ベットは仮想（`is_paper=True`）。live は実際の
資金を投じる運用で、設計もシャドー期間の実績を前提にしている。技術的な
障害は取り除いたが、実金銭を伴う不可逆な移行は判断を仰ぐ事項として
`--mode live` は実行していない。
